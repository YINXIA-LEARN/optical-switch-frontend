# 从一台服务器发出两条消息，看懂集群交换与光交换

假设 A 是推理服务器，B 是另一台计算服务器，C 是调度服务器。A 需要一边向 B 传输一大块数据，一边向 C 报告任务状态。理解这两次通信，只要看两个地方：交换机按什么决定数据去向，以及管理员能通过程序改变什么。

## 普通交换机怎样让三台服务器同时通信

A 的网卡把要发给 B 和 C 的数据封装成以太网帧。若三台机器接在同一台交换机、位于同一二层网络，交换机可以查目的 MAC 地址，把发给 B 的帧送到 B 的端口，下一帧若发给 C 就送到 C 的端口。多个发送方争用同一个出口时，出口带宽有限，帧可能排队。交换机因此能让许多对服务器共享链路，也会在热点出口产生时延。[Cisco 数据中心网络设计指南](https://www.cisco.com/c/en/us/td/docs/dcn/whitepapers/cisco-application-centric-infrastructure-design-guide.html)

机架增多后，常见设计让每架的服务器接入叶交换机，再用脊交换机互连各叶交换机。例如，A 发往另一架的 B 时可以走“A → 本架叶交换机 → 脊交换机 → B 所在架的叶交换机 → B”。机架顶交换机常写作 ToR。机房里也常用光纤连接这些以电子芯片处理数据包的交换机，光纤说明传输介质，设备内部的转发方式还要看设备本身。[Cisco 叶脊设计](https://www.cisco.com/c/en/us/td/docs/dcn/whitepapers/cisco-application-centric-infrastructure-design-guide.html) · [Google 对数据中心光互连的说明](https://cloud.google.com/blog/topics/systems/the-evolution-of-googles-jupiter-data-center-network)

## 光电路交换机怎样改变连接

实验室工具所指的 OCS 是光电路交换机。控制程序先指定某个输入光口接到哪个输出光口，接下来的光信号沿这条光路通过，直到映射再次改变。光开关芯体可以直接改变光的路径，例如 Google 的设备使用可转动的微镜。端点的网卡、光模块以及光路两端的分组交换机仍然可以处理以太网帧。改变连接的控制命令与这条光路承载的业务数据各有用途。[Google 光路示意与工作原理](https://cloud.google.com/blog/topics/systems/the-evolution-of-googles-jupiter-data-center-network)

若 A、B、C 各占一对光纤，当前接通 A 与 B，A 发往 C 的下一帧也会沿 A 当前的光路传输。为了使 C 收到它，可以通过分组网络转发，可以利用另一条链路，也可以协调端点后切换光路。如果端点本身是一台机架交换机，那么一条已接通的机架间光路可以承载两架之间许多服务器的包。这说明光电路交换和分组交换可以用在同一条端到端路径上。[Helios 混合交换实验论文](https://cseweb.ucsd.edu/classes/sp15/cse291-b/papers/p339-farrington.pdf) · [Google Jupiter 生产网络论文](https://research.google/pubs/jupiter-evolving-transforming-googles-datacenter-network-via-optical-circuit-switches-and-software-defined-networking/)

| 关心的问题 | 光电路交换能带来什么 | 适用条件 |
|---|---|---|
| 哪些机架需要更多带宽？ | 可以把已有的端口重新连到通信频繁的机架对，减少业务绕行，也便于调整拓扑。 | 端点速率、光模块与可用端口仍限制容量。已给一对端点使用的光口不能同时按另一套配对使用。[Jupiter 系统设计](https://cloud.google.com/blog/topics/systems/the-evolution-of-googles-jupiter-data-center-network) |
| 能否减少功耗和中间转发？ | 直通光路可以绕过部分电子交换级和中间的光电转换。收益会随可省去的设备、转发级数和流量分布而变化。 | 端点仍需要收发器，光路也需满足光功率预算。每个端口的速率取决于两端设备和链路。[Mission Apollo 光交换系统论文](https://arxiv.org/abs/2208.10041) |
| 短请求与大传输是否获益相同？ | 已经建立的光路能立即承载兼容的流量。需要临时切路时，持续的大传输更有机会摊薄切换代价。 | 应比较端到端的完成时间，包括排队、等待光路、链路恢复和传输。突发小请求可以继续走现成的分组路径。[Helios 实验论文，第 5 节](https://cseweb.ucsd.edu/classes/sp15/cse291-b/papers/p339-farrington.pdf) |

**切换用时与数据通过用时是两项测量。** Helios 研究者用示波器测得某台 Glimmerglass 设备改接光路约耗时 12.1 毫秒，同一原型的同步控制调用约 170 毫秒才返回。这说明“发出命令”“光路接通”和“应用确认传输完成”可以是三个不同时间点。这些数字对应论文中的设备和软件，实验室设备需要单独测量。[Helios，第 5.5 节、图 14](https://cseweb.ucsd.edu/classes/sp15/cse291-b/papers/p339-farrington.pdf)

**生产案例。** Google 在 SIGCOMM 2022 报告了 Jupiter 数据中心网络十年的演进。作者报告这段时期网络资本开支降低 30%、功耗降低 41%，并说明架构同时引入了聚合块直连、光路重构、软件定义流量工程和自动化运维。这些百分比描述的是整套网络演进，不能用来预测单台实验室光开关的节能率。[Jupiter Evolving 论文](https://research.google/pubs/jupiter-evolving-transforming-googles-datacenter-network-via-optical-circuit-switches-and-software-defined-networking/)

## 机房说“可编程”，要看程序改变哪一层

| 设备或接口 | 管理员可以改变什么 | 一个具体例子 |
|---|---|---|
| 普通可管理的分组交换机 | 调整厂家提供的转发功能和参数，例如 VLAN、路由、访问控制和队列。配置也可以自动化。 | 将一组服务器划入同一 VLAN，给高优先级流量分配指定队列。[Cisco 设计指南](https://www.cisco.com/c/en/us/td/docs/dcn/whitepapers/cisco-application-centric-infrastructure-design-guide.html) |
| 支持 OpenFlow 的交换机或 OVS 软件交换机 | 控制程序能给设备提供的流表增删规则，用设备支持的匹配字段和动作组合转发行为。 | 匹配“由某端口进入、目的 IP 为 B”的包，从指定出口转发并统计命中次数。[OpenFlow 1.3 规范，第 2 和第 5 节](https://opennetworking.org/wp-content/uploads/2014/10/openflow-spec-v1.3.0.pdf) |
| P4 数据平面可编程交换机 | 可以描述要解析哪些包头、查哪些表、按什么顺序处理及执行哪些动作，然后针对具体硬件或软件目标编译。芯片资源和支持的操作约束着程序。 | 实验协议增加“任务编号”字段后，可以编写解析和分类逻辑，按任务编号统计流量。之后仍可通过控制接口更新表项。[P4 语言规范](https://p4.org/wp-content/uploads/sites/53/p4-spec/docs/P4-16-v-1.2.3.html) · [P4Runtime 规范](https://p4.org/wp-content/uploads/sites/53/2024/10/P4Runtime-Spec-v1.4.1.html) |
| 软件可控的 OCS | 程序通过管理口或串口改变光端口之间的物理映射。 | 将“输入 1 → 输出 2”改为“输入 1 → 输出 3”，这条输入光路的全部业务一起改变去向。[实验室 16×16 OXC 控制脚本](https://github.com/Mango03111/ANTL-Tools/blob/58fa6cb65f00307f44804624527e98e504484dc2/ocs-sokect-control/chinese-1616-oxc/chinese_ubuntu_optical_control.sh) |

## 回到 ANTL 实验室

仓库里有两份尤其值得对照的文件。归属 `tor-ovs` 的流表脚本使用 OpenFlow 1.3，在软件网桥上按端口和目的 IP 配置转发。归属国产 16×16 OXC 的 `group.txt` 则给出前三组光路映射，端口 1–4 分别按“1↔2、3↔4”“1↔3、2↔4”“1↔4、2↔3”配对。这里的双向箭头表示配置了两个相反方向的输入到输出映射。这两份文件分别说明了对包转发与对光路的控制能力。[OVS 转发脚本](https://github.com/Mango03111/ANTL-Tools/blob/58fa6cb65f00307f44804624527e98e504484dc2/tor-ovs/flow.sh) · [端口映射](https://github.com/Mango03111/ANTL-Tools/blob/58fa6cb65f00307f44804624527e98e504484dc2/ocs-sokect-control/chinese-1616-oxc/group.txt)

如果现场四个独立网口分别接在 OXC 的 1–4 号收发口，以上三组配置就能依次验证四个端点的所有两两组合。源码给出了四网口的命名空间配置，实际机柜中与每个收发光口对应的设备仍需接线表确认。要判断机房那台“可编程交换机”是否支持 P4，则要核对具体设备的型号与厂商提供的编译目标。现有仓库足以演示“改规则”和“改光路”的区别，现场的 P4 能力和现时接线仍待核实。[四网口配置](https://github.com/Mango03111/ANTL-Tools/blob/58fa6cb65f00307f44804624527e98e504484dc2/nic-control/setup-4nic-netns.sh) · [仓库固定版本](https://github.com/Mango03111/ANTL-Tools/tree/58fa6cb65f00307f44804624527e98e504484dc2)
