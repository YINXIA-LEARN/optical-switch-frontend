# 图片制作与素材交接

用于新图、图片编辑、抠图、插画和页面素材。先区分生成栅格图、修改已有图片、调整代码/SVG 图形三类工作，按用户要求、目标格式和当前环境规则选择工具。已有可编辑图标/SVG 系统应优先沿用；需要 AI 图片生成/编辑时使用实际提供的图片工具和适用技能。

## 图片规格

多张图片或需跨任务整合时建立 `.handoff/briefs/images-vN.md`，每张图使用稳定 asset_id；单图可直接写入 task。

| 字段 | 内容 |
|---|---|
| 用途 | 出现在哪个页面/区域，表达什么信息，最终展示大小 |
| 操作 | generate / edit / cutout / export；输入图片路径、版本和参考作用 |
| 内容 | 主体、数量、动作/姿态、场景、必须出现和不能出现的元素 |
| 构图 | 主体位置/占比、镜头/视角、焦点、留白方向与大致比例、允许裁切范围 |
| 风格 | 摄影/插画等媒介、材质、光线、色调；参考图具体借鉴维度 |
| 不变量 | 编辑时须保留的身份、轮廓、服装、标识、构图等；允许修改区域与内容 |
| 文字 | 是否入图、准确文案；UI 标题等通常由页面渲染，用户明确要求图中文字时检查实际拼写 |
| 技术 | 目标像素尺寸、宽高比、格式、背景/真实透明度、文件大小预算（适用时）、是否需要源文件 |
| 输出 | 最终路径、候选数量、版本、预览位置；成套素材需要一致的比例、色板、光照和轮廓语言 |
| 使用 | 页面容器、裁切策略与焦点、桌面/移动端用途、alt 文本及引用位置 |
| 验收 | 内容/技术硬要求、可接受近似、主观判断人、迭代额度 |

把“透明背景”与“白底”“棋盘格背景”区别开。保真编辑与整体重画不同：要求只换背景时不能重画主体。不能承诺生成工具自动保持每个像素或精确输出任意尺寸。

## 实操

1. 实际查看所有目标图及重要参考；核实文件可传给工具。引用明确角色：原图、构图参考、风格参考，避免混淆。
2. 将 brief 转为生成/编辑指令：用途 → 主体/动作 → 构图 → 风格/光线 → 背景 → 保留/排除项 → 技术要求。精确文字和保留项原样传递；仅传工具支持的参数，不臆造接口。
3. 执行获授权的生成/编辑。工具缺失或不支持关键保真要求时报告缺口；不能拿提示词、随手画的替代图或旧图充当新成品。
4. 查看真实返回图，检查主体数量、裁切、文字、边缘与指定保留项；再检查实际文件尺寸、格式和透明度。支持 alpha 通道不等于背景已透明；需要确认透明像素及边缘效果。
5. 不满足硬要求时，在允许额度内定向修正。尺寸不符时仅在用户要求和工具规则允许的情况下裁切/缩放/导出，并检查主体和清晰度；无法合规达到则报告。后处理不是重新生成的证明。
6. 按 asset_id 保存版本与最终选用文件；不要覆盖任务要求保留的原图。记录实际生成/编辑方式、参数摘要、参考来源、尺寸/格式/alpha 结果；没有 seed 等信息写 unknown，不编造可复现性。
7. 整合任务把图放进真实目标容器预览，检查桌面/移动裁切与文字叠加。如果任务只要求制图，交付规定的图片与预览即可，不擅自改业务页面。

批量图片先确保共同风格约束，然后逐张验收；不能因为第一张合格就跳过后续查看。候选仅在任务要求时生成，不默认扩张数量或预算。

## 交付边界

交付清单逐项列 asset_id、最终文件、规格、用途、来源/制作方式、brief 版本和已知偏差。提供可查看的成品；保留目标环境允许的原生媒体输出或本地文件，不为绕过媒体访问限制自行下载。

只有临时 URL 或聊天附件、接收方无法访问时，交接尚未完成；应按环境允许的方式保存/传递，或明确请求补充可访问输入。不能只发“图已生成”。图片生成成功、技术规格通过、风格符合和页面整合完成是不同验收项，分别给证据。
