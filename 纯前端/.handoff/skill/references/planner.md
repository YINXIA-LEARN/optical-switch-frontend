# planner：少往返的批次规划

## 恢复与派单
读启动卡指定任务、STATE 对应行、短 CONTEXT、当前报告/未决项，按需抽查实际文件。planner 换窗口也先确认旧任务板 writer 停止。新项目按 [protocol.md](protocol.md) 建入口和快照；旧任务不重建。

先复用 [verification.md](verification.md) 的环境与证据，再决定调查范围。不要为了派单先替 executor 做完实现或跑一遍验证。能力选择按工具而非模型名。

一个 task 是可连续执行的批次，可组合小修与下一阶段工作。正文用简短结果与索引，包含：
- 窗口/ID/attempt、目标、基线、最小输入、可写范围。
- must/prefer/free 与固定版本 brief；视觉和图片保留专门规格。
- 步骤依赖：哪些可立即做、哪些等具体版本/检查；不把人工验收作为每步默认门槛。
- 检查 ID、验证 owner、环境 profile、需新跑/可复用项和失效条件。
- 缺陷 ID、当轮关闭项/可延期项及关闭门槛；report/evidence/checkpoint 路径。

同能力的连续工作通常合并；不同能力且无写入冲突的任务可并行。只有中间结果影响方案、需要用户选款或实际风险时才插入人工门槛。先保存 task 再更新 STATE，输出带目标与编号的启动卡。

## 多窗口调度
STATE 是单 planner 维护的任务表，不是唯一 current_task 指针。先分配互不重叠的文件、输出和运行资源，再给不同窗口任务卡。共享 app.js、全局样式、锁文件等交给单一 owner；同文件不同函数也不能默认并行写。

使用隔离 checkout 时仍指定集成负责人、基础版本、合并顺序和唯一集成回归；默认复用现有目录，新增 worktree 按宿主规则，不为每个小任务建一份。

依赖可以按步骤满足：页面窗口先做不依赖成品图的布局，图片窗口制图；素材达到约定版本/哈希/检查后再接入。文件存在不等于就绪，需要 planner 审美接受的步骤等 review，其他步骤继续。不用轮询消耗等待时间，到检查点保存并等待触发。

## 审阅与问题分流
默认看增量报告、相关 diff、验收映射和已产出的截图/图片，不默认重跑命令或重拍。只有 verification 的失效条件才补最小范围。主观审美仍需实际看图，但可直接复用执行者截图。

| 情况 | 处理 |
|---|---|
| 在授权范围内的局部问题，执行尚未结束 | executor 当轮自修继续，不先交回 planner |
| 报告文字/索引不一致，但原始证据可核实 | planner 留校正依据；不单为文案启动开发轮 |
| 不阻塞后续独立工作的小缺陷/边界问题 | continue_with_followups，合入下一批 task 并带上后续工作 |
| 破坏关键接口/数据、阻塞依赖、方向性错误 | rework/replan，只阻塞受影响步骤 |

按影响和依赖分类，不按改动行数或“边界情况”名称。数据损坏、隐私/安全问题不能因少见就穿过相关门槛。延期不降低 must：问题保持 OPEN/FAIL/UNKNOWN，指定 ID、接收 task/owner、关闭证据与门槛（通常下个依赖步骤或最终集成前）。无接收任务时明确未派发。最终 accept 前关闭所有必需项，或经用户明确变更范围。

纯修复/接管用原 task 新 attempt；“旧问题 + 新功能”用新 task 引用旧问题 ID，旧 task 标 continued，不留两个活跃修复指派。下一批统一回报多个成果，不为每个步骤发起会话。

## 证据、成本与换窗口
review 只写变化、判断、新待办；复用检查按 ID/路径引用。planner 单写验证索引，不抄日志。最终集成由指定 owner 验证一次，planner 审阅该结果；“最终验收”本身不构成全量重跑理由。

可在 review 末加一行：新跑检查数/复用数、重复运行原因、环境重探次数、额外往返原因。可靠 token/费用可记，无则 unknown；不额外开 Agent 或跑测试只为证明节省。

接管摘要保留已完成、当前改动、未决项、下一步、有效检查与失败尝试路径。新窗口从此恢复，不重复讨论未变事实。变更运行中任务先标 pending_change，确认 writer 停止后派新 attempt；报告终态后 STATE 尚为 dispatched 是正常待审，不要求 executor 改 STATE。
