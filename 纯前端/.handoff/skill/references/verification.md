# 共享环境与一次验证

环境发现按宿主复用，运行验证按影响范围复用。executor 是默认运行者，planner 默认审阅已产出的证据。

## 环境 profile
第一次需要工具的执行者做最小探测，结果放自己 report/evidence；planner 合入 `.handoff/ENV.md`。后续 task 引用 profile ID，无新信息不重写。

每个 profile 只记录：host/运行时标识与实际工作区；成功的工具路径/相关版本、命令/cwd、最近成功 run；浏览器/生成/看图/导出能力及已知限制；运行资源 owner、origin/端口/PID 或分配策略、数据隔离与关闭方式；失败替代和审批要求。旧权限记录不是新会话的授权凭据。

同宿主且无变化信号，直接用已验证命令，不再全机找工具或逐项查版本。新宿主只查本轮需要的能力。路径失效、依赖/配置改变、权限拒绝或实际报错时，仅刷新受影响项；条件未变不反复试已失败方案。共享目录不等于共享工具，不自动安装依赖。

## 检查计划与索引
task 指定一个验证 owner：`check_id → 行为/关键断言 → 输入/环境 → 新跑或复用 → 输出`。沿用现有有意义的检查，不为每个函数补测试；共用集成检查交给唯一集成 owner。

planner 管 `.handoff/VERIFICATION.md` 短索引：

| check_id | 范围/关键断言 | owner/run_id | baseline/inputs/env | 结果与证据 | 失效条件 |
|---|---|---|---|---|---|
| 示例 save-reload | 同 origin 刷新保持 ID/内容 | W-code/T010-a1-r1 | 相关源码/依赖版本/E-local | PASS，结果路径 | 加载/保存逻辑、schema、配置改变 |

索引只引用原始结果。每个 run 记录命令/参数、cwd、相关代码/素材/配置身份、环境、时间、退出码/状态、断言和证据。Git 可用版本+相关 diff，无 Git 用相关哈希；不必每轮哈希全库。哈希不代替行为验证。

复用 PASS 须满足：覆盖当前条件；相关源码/依赖/输入/配置未变或可确定变更不影响；证据可读且环境适用。标 reused_from 与依据，不将旧结果标“本轮运行”。影响不明就跑相关检查；文件名相同不保证版本相同。

## planner 补跑条件
默认不跑。只在以下情况补最小范围，并先记录原因：
1. 相关变化导致原证据失效。
2. 缺关键断言/结果、报告冲突或真实现象与证据矛盾。
3. task 预定独立检查，或新发现明确高影响风险。

缺一个断言就补一个断言；现成套件不能方便拆分时可运行套件并说明。确认有效后不反复加测。最终集成覆盖最终组合的变化一次，不因 planner 换窗口或结束阶段重新全测。

UI 审阅现有真实截图，图片查看已交付文件；相关代码变化、截图缺状态或证据异常才重拍。服务重启不自动使纯代码测试过期，但持久化检查必须保持同 origin。

## 并发证据
运行前后确认相关被测输入稳定；被其他任务并发修改影响的 run 标 stale，稳定后再测，不能标 PASS。服务/输出按任务隔离或明确共享 owner；不重启或结束别人服务。共享 ENV/索引由 planner 单写，executor 只写自己任务的 run 文件。
